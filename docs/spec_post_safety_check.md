# 子ども向けSNS 投稿安全判定システム 仕様書

## 1. 概要

### 1.1 目的

本システムは、小学校低学年を対象としたSNSにおいて、安全な投稿を支援することを目的とする。

投稿内容に対し、

* 暴言・誹謗中傷
* 個人情報
* 外部SNSへの誘導
* 外部連絡先の共有

などを検知し、子どもにも理解できる分かりやすいアドバイスを提示する。

従来の「AIのみで判定する方式」ではなく、独自の解析エンジンを前段に配置することで、

* 判定精度向上
* 処理速度向上
* Gemini API利用量削減
* 判定理由の説明性向上

を実現する。

### 1.2 スコープ外（本フェーズでは対応しない）

* **画像投稿の安全性判定（OCR含む）**: 「15. 今後の拡張候補」に繰り越す。
* **DM投稿の判定**: DM機能自体が別ブランチ（`native-setup`）でプロトタイプ実装されているのみで、`dev`未マージかつ認証未実装のため、DM機能が正式にリリースされるまで対象外とする。

既存の添削モード（`functions/gemini_utils.py` の `validate_and_analyze_post`）が担っていた安全性チェックを、本仕様の判定エンジンに置き換える。バズり／炎上演出用の分析（いいね数予測等）は既存ロジックを維持しつつ、Gemini呼び出し回数が増えないよう同一リクエストにまとめる（詳細は10章）。

# 3. 対応する投稿

## 3.1 テキスト投稿

投稿本文を解析し、安全性を判定する。本仕様が対象とするのはテキスト投稿のみとする。

## 3.2 既存の添削モード／自由モードとの関係

* 判定エンジン（本仕様の処理フロー）は **添削モード・自由モードの両方** に対して実行する。
* ただし、投稿のブロックおよびNG理由の表示（`NgReason`モーダル等）は **現行仕様どおり添削モードのみ** で行う。
* **自由モードでの判定結果は保存・表示せず破棄する**。将来的に保護者向け管理機能（15章）で活用する可能性はあるが、本フェーズでは対応しない。

# 6. テキスト解析

## 6.1 使用ライブラリ

* **SudachiPy + GiNZA（spaCy）をフェーズ1から採用**

## 6.2 辞書のロード方式

* GiNZA/SudachiPyの辞書は **アプリ起動時にダウンロード・ロードし、メモリに保持** する（リクエスト毎にロードしない）。
* 運用上の注意: デプロイ環境（Render等）で起動のたびに外部から辞書をダウンロードする構成は、起動時間の増大やダウンロード失敗時の障害につながるリスクがある。安定運用のためには、デプロイイメージに辞書を同梱する方式への切り替えも代替案として検討する。

## 6.3 解析内容

* 形態素解析
* 品詞解析
* 原形取得
* 係り受け解析 — **条件付き採用**。フェーズ1でGiNZAによる実運用検証を行い、レイテンシ等の観点で現実的でないと判断された場合は、本仕様から除外し将来フェーズへ繰り越す。

# 7. ルールベース判定

辞書を用いて暴言を検出する。

例

| --- | --: |
| 死ね  | 100 |
| 殺す  | 100 |
| ばか  |  40 |
| きもい |  30 |
| うざい |  20 |

* 超

対象

* 死ね

検出対象

### 学校

* 学校名

### 地域

* 市区町村
* 住所
* 駅
* 公園

### 連絡先

* 電話番号
* メールアドレス
* URL
* LINE ID
* Discord
* Instagram
* TikTok

### その他

* 習い事
* 部活動
* 塾

### 辞書データの調達元

# 10. Gemini

Geminiは最終判定のみ担当する。FastAPI側で解析した情報を入力として渡す。

## 10.1 既存Gemini呼び出しとの統合

現行の添削モードでは、`validate_and_analyze_post` が安全性チェック（`is_safe`, `safety_reason`）とバズり／炎上演出用の分析（`is_positive`, `predicted_likes`, `reaction_types` 等）を **1回のJSON出力にまとめて** 実施しており、API利用量を抑えている。

本仕様の最終判定Geminiコールは、この既存呼び出しを **置き換える形で統合** し、以下を同一リクエストで返却させる。

* 安全性の最終判定（ルールベース判定が曖昧なケースの判断）
* 子ども向け説明文の生成（11章のテンプレートを整形）
* 既存のバズり／炎上演出用の分析結果

これにより、Gemini API呼び出し回数を増やさずに済む。

## 10.2 入力例

```json
{
  "text":"今日は○○小学校から帰った！",
  "risk":{
    "abuse":0,
    "personal":40,
    "external":0
  },
  "detected":[
    "学校名"
  ]
}
```

## 10.3 Geminiの役割

* 曖昧なケースの判断
* 最終判定
* 子ども向け説明生成

# 11. アドバイス生成

基本はテンプレート方式とする。

### 学校名

```
学校名を書くと、
知らない人にも通っている学校が分かってしまうよ。

「学校」と書くと安心だよ。
```

### 電話番号

```
電話番号は
知らない人に見られると危ないよ。

投稿から消してみよう。
```

### 暴言

```
読む人が悲しい気持ちになるかもしれないよ。

やさしい言葉に変えてみよう。
```

### 住所

```
住所を書くと、
住んでいる場所が分かってしまうよ。
```

Geminiはテンプレートを基に、自然で分かりやすい文章へ整形する役割を担う。

# 12. データ構造

```python
@dataclass
class DetectionResult:
    category: str
    subtype: str
    matched_text: str
    score: int
    position: tuple[int, int] | None
    confidence: float
```

全ての検出器はDetectionResultを返却する。

## 12.1 判定結果の保存

* **添削モード**: 安全性NGと判定した投稿は、現行の `rejected_posts` コレクションと同様の形で記録する。
* **自由モード**: 判定結果は保存しない（3.2節参照）。

# 16. 本システムの特徴

* AIに依存しない独自の判定エンジンを実装
* 表記ゆれを考慮した高精度な前処理
* 辞書・正規表現・形態素解析を組み合わせた多段階判定
* 単語ではなく「情報の組み合わせ」による危険度推定
* Geminiは最終判断と子ども向け説明に限定し、既存のバズり分析コールと統合することでAPI利用量を削減
* テンプレートベースのアドバイスにより、一貫性・説明性・処理速度を向上
